# acmg-total-scheduler CHANGELOG

2026-10-15 description 瘦身整改：version 变更日志从 SKILL.md frontmatter 下沉至此

## v4.0.0

- 新增遗传方式前置判定硬步骤：PVS1/PM3/PS2/PM6/PP1 等依赖遗传模式的证据码判定前，必须先调用 `arad-inheritance-judgment` 子技能确认该变异的 AD/AR 遗传方式，多模式基因须明确对应关联疾病，禁止默认 AD 或 AR。

## v4.1.0

- 新增【可疑文献上报】全局硬约束：所有涉及查文献的证据码（PVS1/PS2-PM6/PS3-BS3/PS4/PM3/PM5-PS1/PM2/PP1/BS2/PM1/PP2），命中可疑文献判定标准时，必须把 PMID+链接+原因上报用户人工核验，不得把无法核验全文的文献静默当作已核实证据（Rath 2015 PMID 26540129 判例）。

## v4.2.0

- 升级可疑文献判定：ClinVar/HGMD 挂载文献一律默认可疑（无条件上报）；其他检索路径按”变异本体可核验性”分 L1(不可核验/假阳性)/L2(部分可核验)/L3(已核验)。

## v4.3.0

- 新增【按用途证据码定制文献提取】：每个涉及查文献的证据码检索时须声明用途，按”证据码→关键提取字段映射表”差异化提取（PM3=合子+反式+相位、PS4=先证者数+OR+CI、PS2/PM6=de novo+双亲验证、PS3/BS3=实验+对照+结果、PM5/PS1=同位点变异、PVS1=下游热点、PP1=分离次数、BS2=健康成人合子态），关键字段缺失须逐字段标”未报告”，不得用通用模板填充。

## v4.4.0

- 新增【执行纪律】：中间步骤须显式列出待判定清单并逐一勾选状态(✓已调用/✗未适用注原因/⚠待核验)；进入收尾前须做”圈定清单 vs 实际判定清单”逐码核对，缺码不得定级；调用须写完整技能名(ev-xx)防同名混淆。

## v4.6.0

- 新增【已读证据方向衔接】：中间判定读到的外部证据方向（ClinVar EP/多星 P/LP、ClinGen 有效性/VCEP、已核验 PMID）必须保留记录，作为收尾 `acmg-conflict-summary-output` §0.6 证据方向一致性校验输入，方向相反（已读 P/LP 但净方向 VUS/良性）时禁止定级、须回中间复核。

## v4.6.0

- 新增【互斥唯一裁决声明】：互斥的裁决唯一发生在收尾技能 `acmg-conflict-summary-output` §1.1 互斥矩阵，各 ev-* 子技能互斥段落仅为提示，冲突以矩阵为准；同时新增【版本绑定与过期守卫】铁律——所有外部阈值/规则（人群频率、REVEL 切点、SpliceAI 0.2、LOF 频率 0.1%、基因特异性阈值、cspec/PMID 等）必须在输出标注来源+版本，官方升版触发重审，禁止使用无版本绑定的旧阈值。

## v4.7.0

- 补齐六个缺失良性证据码（BS4/BP1/BP2/BP3/BP5/BP7），覆盖完整 ACMG 2015 良性清单：BS4→`ev-pp1`、BP1→`ev-pp3-bp4`、BP2→`ev-bs1-bs2`、BP3→`ev-pm4`、BP5→`ev-ps2-pm6`、BP7→`ev-pp3-bp4`，证据适用表与良性负分已同步更新。

## v4.8.0

- 新增【arad 前置降级铁律】（整改 P0-3，外部评审风险1）：`arad-inheritance-judgment` 判定失败/查不到时，不得让下游证据码卡死——总调度显式标注"遗传方式未确认"，依赖遗传模式的证据码（PVS1/PM3/PS2/PM6/PP1 等）各自按"证据不足"处理并写出口，流程继续走完①圈定→中间判定→收尾，不得中断；arad 自身"第0步双模式基因确认"保留，失败时走降级出口。

## v4.9.0

- 新增【两级官方优先】（整改 var023 CFTR 5T 盲区）：§0 适用前提与证据来源铁律第4条的”VCEP 官方优先”从”仅 ClinGen VCEP/EP cspec”扩展为两级——①第一级 ClinGen VCEP/EP cspec 对本变异（具体到 c.HGVS/rsID）的官方裁定（原规则保留）；②第二级：基因无 ClinGen VCEP cspec，但存在

## v4.10.0（全局维护收敛整改，与 11 个 ev-* 子技能同步）

- ①可疑文献判定完整标准（L1/L2/L3 分级 + 挂载默认可疑 + 强制上报）收敛到唯一权威 `ev-variant-literature-patient`，本调度层仅保留"哪些证据码涉及 + 强制动作 + 影响 + 铁律"声明，不再内嵌完整判定标准；②PM1+PP3 软提醒正文收敛为一行声明，唯一权威在收尾 §1.1+§3。

## v4.11.0（评级结果永久归档，联动收尾 v5.3.1）

- 新增**评级结果归档命中检查**：评变异前先查 `acmg_cache.py` 的 `result` 命名空间（已确认评级结果永久归档），命中复用须显式标注 `rated_at / skills_version / data_snapshot`；定级完成后按收尾 §3.5 写入归档，评过的变异下次命中（慢优化收口，防重复外部检索）。

## v4.12.0（时效守卫硬化 + 脚本化，联动收尾 v5.3.2 / acmg_cache v1.2.0）

- **命中不是无条件直接终审，必须先过时效守卫**：任一触发（① `rated_at` 距今 > 90 天；② `data_snapshot` 缺失 / 任一数据源升版或取数过旧；③ `skills_version` 落后当前技能群版本）→ **强制走完整重评并 upsert 覆盖归档**，不得直接复用。
- **时效守卫固化为确定性脚本**：命中时运行 `python scripts/acmg_cache.py check --ns result --key "<基因|c.HGVS>"`，按脚本 STATUS（REUSE / RERATE / NOT_FOUND）+ 触发闸与原因执行，**不得由执行者凭读字段自行判断**；result 是唯一永久命名空间，原始查询缓存仍按 TTL 过期。
