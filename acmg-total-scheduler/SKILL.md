# ACMG 总调度层（评级唯一入口）

> **本 SKILL 是评级一个变异的唯一入口。** 评级流程固定为：**① 先出"圈定清单" → 中间逐个调用证据码子SKILL判定 → 最后进入「互斥与汇总输出」收尾**。
> 本 SKILL 负责第①步圈定：输出"该变异类型可用的证据码集合 + 对应子SKILL + 该码默认分值"；**判定证据是否成立、用哪个使用等级，由各证据码子SKILL 负责，本 SKILL 不判定证据成立性**（分值是圈定基线，不是最终使用等级；最终等级由子SKILL 按实际证据定，见下方分值判定表）。

## ⚠ 强制流程硬约束（写死，不得跳过）

**评级任何变异，必须严格按下列顺序执行，缺任何一步都不得输出定级结论：**

0. **前置步骤**：**①先查"已确认评级归档"**（见下方「评级结果归档命中检查」，v5.3.1）——命中则直接复用该变异已确认的评级结论，并显式标注 rated_at/skills_version/data_snapshot（结论所基于的数据时点），不重复外部检索；未命中才继续后续完整流程；**②完成变异身份归一化**（见下）；**③调用 `arad-inheritance-judgment` 子技能完成遗传方式前置判定**（确认 AD/AR/多模式及 LOF 是否为已知机制），把"遗传模式"写入圈定清单作为后续证据码判定的前提；
1. **第①步（本 SKILL）**：先按变异类型查"证据适用表"，**只在打√的证据码里收集**，打×的直接不考虑，输出"圈定清单"；
2. **中间步骤**：对圈出的每个证据码，**逐个调用对应子SKILL 判定**，记录每个证据码的"使用等级 + 出处(PMID/数据库)"；不得略过、不得凭经验直接给强度；**依赖遗传模式的证据码（PVS1/PM3/PS2/PM6/PP1）判定时须引用前置步骤得出的遗传模式**；
3. **最后步骤**：进入「互斥与汇总输出」SKILL，按互斥矩阵消解冲突（互斥对只保留分值更高、更可信的那个证据码、丢弃另一方），并完成官方已定级优先、方向一致性校验与双套定级；**缺这一步不得输出定级结论**。

> **⚠ 执行纪律（硬约束，原 v4.4.0）**：中间步骤须显式列出待判定清单并逐一勾选状态(✓已调用/✗未适用注原因/⚠待核验)；进入收尾前须做"圈定清单 vs 实际判定清单"逐码核对，缺码不得定级；调用须写完整技能名(ev-xx)防同名混淆。（与下方 1-5 条执行纪律一致）

> **⚠ VCEP 衔接（原 v4.5.0）**：有 ClinGen VCEP 规范的基因，先检查本群是否装载 `clingen-vcep` 载体（`gene-gn-file-mapping.csv` 与 `VCEP-<基因>.md`）；已装载则按基因特异性规则判定（不走通用调度），未装载则显式标注『VCEP 载体缺失，暂走通用调度』，不得静默、不得谎称已按 VCEP 判定。**VCEP 仅辅助 + 强制网上核实：clingen-vcep 只是快速检阅通道，不是最终依据；每次过证据码群用到 VCEP 规则时，必须先联网核实 ClinGen cspec 最新版，实际输出以数据库最新更新为准。**

> **SF 报出与 PGT 决策不属本评级群**：已拆分至独立携筛-WES-PGT遗传咨询技能群（总入口 `carrier-screen-wes-pgt-counseling` / `acmg-sf-report-scope` / `wes-reporting-rules`），评级完成后如需判定次要发现报出或 PGT-M，转到该群处理，本群不承担报出判定。

> **第①步（圈定，对应第 1 条）**：按变异类型（Truncating截短/Missense错义/In-frame indel框内缺失/Synonymous同义）从"证据适用表"圈定本变异可使用的证据码集合，并给出每个可用证据码对应的子SKILL与分值。资料来源：《指南解读》、《变异解读查询路径》及"致病性变异证据适用的变异类型表"。
> 本技能群由 23 个技能组成（ev-* 19 个 + 调度/收尾 3 个 + VCEP 载体 1 个：acmg-total-scheduler、acmg-conflict-summary-output、arad-inheritance-judgment、clingen-vcep），中间步骤需逐个调用证据码子SKILL。**执行时必须满足：**
> 1. **显式列出待判定清单**：在进入中间步骤前，先输出"圈定清单"——每个圈出的证据码**必须写明其对应子SKILL 名称**（如 PM3→`ev-pm3`、PVS1→`ev-pvs1`），不得笼统写"各证据码"；
> 2. **逐码勾选状态**：对圈定的每个证据码，判定后须逐一标注 **✓已调用 / ✗未适用(注明原因) / ⚠待核验**，不得整段跳过、不得以"该码不适用"一笔带过而不说明依据；
> 3. **依赖遗传方式的证据码（PVS1/PM3/PS2/PM6/PP1）**：判定时必须引用前置步骤得出的遗传模式，并写明"本码判定依据的遗传方式=____"；
> 4. **圈定清单 vs 实际判定清单逐码核对**：进入「互斥与汇总输出」前，**必须**把"第①步圈定的证据码集合"与"中间步骤实际判定过的证据码集合"逐码比对——凡圈定却未判定的，必须补判或明确标注"不适用/证据不足"，缺码不得进入定级；
> 5. **防同名混淆**：技能名均以 `ev-` 前缀区分，调用时**不得**把 `ev-pm3` 当 `ev-pm3-bp4`、不得把 `ev-pp3-bp4` 当 `ev-pm3`。中间步骤输出须写**完整技能名**（`ev-xx`），禁止缩写。

## ⚠ 证据来源铁律（全局，适用于本调度层及其全部子SKILL）

1. **任何证据码是否成立、用哪个等级，一律严格按对应证据码子SKILL 的流程与阈值表判定**（逐个调用子SKILL、对号阈值、给出数据→档位→等级闭环），不得跳步、不得凭经验或外部工具的"结论性评级"直接给强度。
2. **GeneBe 使用边界（强制）**：GeneBe **仅允许作为基础注释取数通道**——转录本信息、核苷酸改变(c.HGVS)、氨基酸改变(p.HGVS)、外显子信息、hg19/hg38 坐标、软件预测分值（REVEL/AlphaMissense/BayesDel/SpliceAI 等）。**GeneBe 返回的任何评级判断字段（`acmg_classification` / `acmg_criteria` / `acmg_score` / `clinvar_classification` / `clinvar_submissions_summary` 等）对变异证据的判断均不可用**，一律不得作为任何证据码的判定依据。
3. 各子SKILL 中凡标注 GeneBe 的 `acmg_*` / `clinvar_*` 为"参考/兜底/辅助"的，一律按本条铁律收紧为"仅限基础注释取数，评级字段不得引用"。
4. **VCEP 仅作辅助与快速检阅通道，每次过证据码群必须网上核实（强制）**：**仅当本群已装载 `clingen-vcep` 载体**（`gene-gn-file-mapping.csv` + `VCEP-<基因>.md`）时适用本条第 4 条；**未装载时直接跳过 VCEP 分支并显式标注『VCEP 载体缺失』，不得静默、不得谎称已按 VCEP 判定**。已装载时：`clingen-vcep`（ClinGen VCEP 规范本地缓存）**不是最终依据**。凡要用 VCEP 基因特异性规则：
   - 必须先联网到 **ClinGen cspec（https://cspec.genome.network/）** 核实该基因对应 VCEP/GN 最新规范；
   - **实际输出一律以数据库/官网最新更新为准**；本地知识与官网一致才可采用，不一致以官网为准并在输出标注差异；
   - 官网核实不通过/无法访问时，本地数据仅作参考提示，标注"未经官网核实"，不得作为定级依据；
   - VCEP 特异性阈值（PM2 频率、PP3 REVEL 界值等）使用时，仍须到对应数据库（gnomAD/ClinVar/REVEL 等）实时取数核实。
   - **SF 报出 / PGT 决策不属本群**：本群只做变异评级；评级完成后的次要发现(SF)报出、WES 报出、PGT-M 决策，转至独立携筛-WES-PGT遗传咨询技能群（总入口 `carrier-screen-wes-pgt-counseling`，子技能 `acmg-sf-report-scope` / `wes-reporting-rules`）处理。
5. **【两级官方优先】（v4.9.0 新增，总调度侧落点，治 var023 盲区）**：官方优先分**两级**，收尾统一在 `acmg-conflict-summary-output` §0 前置裁决，本调度层及各 ev-* 子技能在圈定/判定前先做两级识别：
   - **第一级 ClinGen VCEP/EP cspec**（原 v4.5.0 规则，保留）：基因有 ClinGen VCEP cspec 且对**本变异（具体到 c.HGVS/rsID）**给出官方分类结论 → 优先采用官方结论，通用判定不得覆盖。
   - **第二级 非 ClinGen 权威专家组共识**（v4.9.0 新增）：基因**无 ClinGen VCEP cspec**，但存在**权威专家组/官方技术标准的共识性定级**——三要素：①权威性（ACMG 官方专项技术标准/专项指南、基因特异 Expert Panel 共识库如 CFTR2、ClinVar 专家评审标注 reduced-penetrance/variable-expressivity 等；**非** ClinVar 一般提交者聚合分类、非单篇文献、非工具评级字段）；②具体性（对**本变异或具体等位/变异组**给出明确 P/LP/B/LB 分类 + 外显率特征）；③可溯源（能联网核实来源+版本+结论）。**有该共识 → 优先采用共识定级为最终分类；通用分值法（尤其对低外显率/可变外显率等位——非经典全外显、PVS1 不适用，通用分值系统性低估，如 CFTR 5T 通用仅 +2 VUS）不得覆盖该共识**，交付显式标注"非 cspec 官方，按权威专家组共识定级（来源+版本+结论）"。
   - **无 cspec 亦无权威共识** → 走通用调度，标注"无 ClinGen cspec 亦无权威专家组共识，按通用调度"。
   - 判据与裁决以收尾 `acmg-conflict-summary-output` §0 前置【官方已定级优先（两级）】为唯一依据，本调度层与 ev-* 子技能仅做识别与留痕，不做最终裁决。

## ⚠ 可疑文献上报（全局硬约束，引用唯一权威，v4.10.0 收敛）

**凡证据码判定依赖文献检索（包括但不限于：PVS1 下游热点/病例数、PS2/PM6 新发文献、PS3/BS3 功能实验、PS4 先证者数/OR、PM3 反式病例、PM5/PS1 同位点文献、PM2 频率文献、PP1 共分离、BS2 健康成人、PM1 功能域/热点区域文献、PP2 错义机制文献），必须执行"可疑文献上报"机制（L1/L2/L3 分级 + 挂载默认可疑 + 强制上报的完整判定标准，**唯一以 `ev-variant-literature-patient` 为准**），不得把无法核验的文献静默当作已核实证据。**

- **第一类（一律可疑，无条件上报）**：ClinVar/HGMD 挂载文献一律默认可疑，须逐条输出 PMID+链接+原因 交用户人工核验，或全文核验（L3）通过后才可计入证据（判定标准唯一以 `ev-variant-literature-patient` 为准）。
- **第二类（其他路径按可核验性分级）**：PubTator / LitVar2 / PubMed / LitSense / OpenAlex / Semantic Scholar / EuropePMC / 搜索引擎 / 中文检索命中的文献，按 L1/L2/L3 分级（判定标准唯一以 `ev-variant-literature-patient` 为准）——L1 不可核验/假阳性→强制上报剔除或人工核验；L2 部分可核验→上报标注"需全文核验该具体变异"；L3 变异本体已核验→正常计入，全文核验后更可靠。

**强制动作**：把该 PMID + 链接 + 可疑原因（含来源：ClinVar/HGMD挂载 或 检索路径+等级）**逐条输出给用户**，请用户人工核查或下载全文回传；在用户确认前，该文献**不得作为任何证据码的已核实数据计入**。

**影响**：若某证据码唯一/主要支撑是可疑文献，则在该文献核验完成前，该证据码等级判定须标注"待全文核验"或暂不成立，并在输出中如实写明。

**铁律**："自动检索层全部为空" ≠ "全文没有"；HGMD/ClinVar 挂载的 PMID 极可能把变异列在 Table/正文中（标题摘要不可见），必须人工全文核验（Rath 2015 PMID 26540129 判例：F7 c.379T>C 列于 Table 1，标题摘要检索不到，仅全文可见）。

## ⚠ PM1 + PP3 合计封顶 Strong（Pejaver 2022，唯一权威在收尾）

PM1（功能域/热点区域，2 分）与 PP3（计算机预测有害，1/2/4 分）不在硬互斥红格内，允许同用；但二者证据维度部分重叠，存在重复计入风险，**合计计分封顶 Strong（+4），不得各自全分累加**。**本调度层仅作识别、不内嵌完整封顶规则与文案，最终封顶规则与输出位置唯一以「互斥与汇总输出」§1.1 及 §3 为准**（详见收尾 SKILL）。

## 0. 适用前提（先核对）

- 适用于符合孟德尔遗传规律的基因变异解读。
- **若该基因有基因/疾病特异性指南（RASopathy、CDH1、PTEN、Hearing loss、MYH7、PAH、DICER1、RUNX1 等 ClinGen VCEP），优先用特异性指南，不走本通用调度。** 具体判断方法：**先检查本群是否装载 `clingen-vcep` 载体**（`gene-gn-file-mapping.csv` 与 `VCEP-<基因>.md` 文件）——**已装载**：查 mapping 确认该基因是否有对应 `VCEP-<基因>.md` 规范，有则按 clingen-vcep 的基因特异性规则判定（含强度拆分、积分制、不适用证据码、互斥条款），无则走本通用调度；**未装载（当前环境即缺失）**：显式输出『⚠ VCEP 载体缺失，本次跳过基因特异性判定，暂走本通用调度；如该基因确有 VCEP 规范，须补装载体后重评』，不得静默跳过、不得谎称已按 VCEP 规则判定。**无 ClinGen VCEP 时查第二级（v4.9.0）**：该基因无 ClinGen VCEP/cspec 时，**再查是否存在非 ClinGen 权威专家组共识定级**（CFTR2 Expert Panel、ACMG 官方专项技术标准/专项指南、ClinVar 专家评审 reduced-penetrance/variable-expressivity 等）——有则**优先采用该共识定级，不走通用分值**（尤其低外显率/可变外显率等位，通用分值系统性低估，如 CFTR 5T）；无则走本通用调度，标注"无 ClinGen cspec 亦无权威专家组共识"。判据以收尾 `acmg-conflict-summary-output` §0 前置【官方已定级优先（两级）】为唯一依据。
- **评级完成后的可选步骤（转携筛-WES-PGT群，本群不承担）**：评级出结果（P/LP/VUS/LB/B）后，如需判定该变异是否作为 ACMG Secondary Findings（SF）次要发现报出、是否可支持 PGT-M、报进主表/副表哪个位置，**转至独立携筛-WES-PGT遗传咨询技能群**（总入口 `carrier-screen-wes-pgt-counseling`：`acmg-sf-report-scope` 判 SF 报出、`wes-reporting-rules` 判 WES/panel 报出位置、`pgt-genetic-counseling` 判 PGT-M 决策）；本评级群不做报出判定。
- 转录本需与 ClinVar/HGMD 对齐；不一致用 Mutalyzer Position Converter 转换（https://v2.mutalyzer.nl/）。

## ⚠ 变异身份归一化（前置硬步骤，防命名/编号错失）

**评级任何变异前，必须先完成变异身份归一化，否则不得进入证据码检索。** 目的：避免同一物理变异因转录本编号差异/前肽编号偏移/深内含子另编号被误判为不同变异，导致检索错失（对应 TACT L2 命名边界问题）。

**固定四段：**

1. **解析规范转录本**：确定该基因的 **MANE Select 转录本**（VariantValidator / GeneBe 基础注释 / Ensembl VEP），并把用户给定转录本与 MANE 对齐；
2. **解析规范等位基因标识**：尽量解析 **ClinGen Allele Registry CA ID**（https://reg.genome.network/allele ）与 **rsID**，作为跨库匹配主键；
3. **建立检索同义词组**：把该变异的所有已知别名列为同义词组——转录本编号差异（如 GALC L618S=Leu634Ser）、前肽编号偏移（如 F7 Thr219Asn=Thr241Asn）、深内含子另编号（如 SLC12A3 c.2521+253C>T=c.2548+253C>T）；检索时**按同义词组并行查询**；
4. **同位点/反式对匹配基于 CA ID**：PS1/PM5 同位点识别、PM3 反式对匹配，须基于 CA ID/rsID 而非单一转录本描述。

> 变异身份归一化可复用 `ev-variant-standardization` 技能的 CA ID/坐标对齐能力；归一化只做身份匹配，不改变任何证据码标准。

> **归一化唯一入口（主/候补两级，v4.6.0）**：变异身份归一化的**唯一主入口为 `ev-variant-standardization`（GeneBe 主流程）**——评级任何变异做身份归一化，一律优先调用它；`ev-disease-info` 附录的变异标准化流程（ClinVar esummary + AutoPVS1 + Mutalyzer）仅作**候补**：**仅当 `ev-variant-standardization` 主流程无法返回结果**（GeneBe 网络不可达 / 该变异无收录 / 输入格式不支持 / 请求超时）时，才可降级启用候补。**主流程可用时禁止改走候补**，避免两套流程转录本/命名口径漂移。归一化只做身份匹配，不改变任何证据码标准。

> **⚠ 评级结果归档命中检查（v5.3.2 硬化，慢优化收口，防重复外部检索 + 防过期结论复用）**：
> 评一个变异前，**先查 `scripts/acmg_cache.py` 的 `result` 命名空间**（已确认评级结果的**永久归档**）。命中**不是无条件直接终审**，必须先过"时效守卫"——**判定固化为脚本（v1.2.0），不得由执行者凭读字段自行判断**：
> - **强制动作（命中时，写死）**：运行 `python scripts/acmg_cache.py check --ns result --key "<基因|c.HGVS>"`——脚本自动读归档条目（`rated_at` / `data_snapshot` / `skills_version`），与当前技能群版本 + fresh_days=90 对比，输出 STATUS：
>   - **`REUSE`**（三道闸全过）→ 可复用，但输出仍须显式标注 `命中已确认评级归档：rated_at=__ / skills_version=__ / data_snapshot=__`，作为**候选基线**由交付确认；**高危位点（ClinVar EP/多星、HGMD 挂载、P/B 高置信）或官方裁定可能变化时，命中复用仍须人工确认，不得仅凭命中直接定级**；
>   - **`RERATE`**（脚本输出触发闸与原因：① `rated_at` 距今 > 90 天；② `data_snapshot` 缺失 / 任一数据源取数过旧 / 数据源已升版（归档版本 < 当前）；③ `skills_version` 落后当前技能群版本）→ **不得直接复用，必须走完整流程重评**（重评后按收尾 §3.5 upsert 覆盖归档，更新 rated_at / data_snapshot / skills_version）；
>   - **`NOT_FOUND`**（无归档）→ 走本 SKILL 完整评级流程，定级完成后按收尾 §3.5 写入 result 归档，评过的变异下次命中。
> - **边界（写死）**：result 是**唯一永久命名空间**；gene_disease/vcep/genebe/freq/revel 原始查询缓存仍按 TTL 过期（外部库升版会改频率/分类/官方裁定/预测分值，永久化会引入过期数据）。归档是"结论快照"，命中必须过 `check` 脚本时效守卫 + 标注 data_snapshot，**不静默当最新**。

## ⚠ 遗传方式前置判定（硬步骤，v4.0.0 新增，PVS1 等证据码判定的前提）

**评级任何变异前，必须先调用 `arad-inheritance-judgment` 子技能确定该变异/基因的遗传方式（AD / AR / 无法推断），否则不得进入 PVS1、PM3、PS2/PM6、PP1 等依赖遗传模式的证据码判定。** 目的：避免"未判遗传方式就用/不用 PVS1"或把多模式基因（如 ACD 同时关联 AD 与 AR 表型）错误默认，导致证据码判定失准。

**固定执行方式：**

1. **调用子技能**：运行 `arad-inheritance-judgment`（查 ClinVar + PubMed 患者基因型 + 同基因同类型变异），并结合 ClinGen GenCC 的关联疾病与 MOI 字段，输出该变异的遗传模式；
2. **多模式基因处理**：若基因关联多种遗传方式（如 ACD=AD 的 DKCA6 + AR 的隐性端粒病 + semidominant 短端粒综合征），须**明确该变异对应哪个关联疾病**，不可笼统按单一 OMIM 条目默认；LOF 变异是否适用 PVS1，取决于该关联下 LOF 是否为已知机制；
3. **写入圈定清单**：把「遗传模式 + LOF 是否已知机制」作为圈定清单的前置结论输出，供 PVS1/PM3/PS2/PM6/PP1 子SKILL 判定时引用；
4. **查不到/无法推断**：明确写"无法推断"，PVS1 等依赖遗传模式的证据码按"证据不足"处理，不得擅自假设 AD 或 AR。

> **⚠ arad 前置降级铁律（v4.8.0 整改 P0-3，强制，防单点失败传导）**：若 `arad-inheritance-judgment` 调用失败、查不到该基因/变异、或 ClinVar+PubMed+GenCC 三方均无 MOI 信息而无法确认遗传方式——**流程不得中断、不得卡死**，按下述出口处理：
> 1. **总调度标注**：输出显式标注"**遗传方式未确认（arad 无结果），依赖遗传模式的证据码按证据不足处理**"，写入圈定清单前置结论；
> 2. **依赖遗传方式证据码各自走"证据不足"出口**（不得静默跳过，须在"圈定↔判定逐码核对表"注明原因）：
>    - PVS1：标注"遗传方式未确认，LOF 机制适用性无法判定→证据不足/待人工"；
>    - PM3：标注"无法确认 AR，反式计分前提不成立→证据不足/不适用"；
>    - PS2/PM6：标注"遗传方式未确认，de novo 证据降级处理/待人工"；
>    - PP1：标注"遗传方式未确认，LOD 公式（AD/AR）无法选用→证据不足"；
>    - 其余依赖 MOI 的码同样按"证据不足"出口；
> 3. **收尾正常执行**：`acmg-conflict-summary-output` 照常收尾，最终分类按"遗传方式未确认"语境保守输出并标注待人工复核，**不中断评级流程**；
> 4. **多模式基因未定**：arad 能给出多模式列表但无法确定当前变异对应关联疾病时，同样走降级出口（标注"多模式未定，按保守语境处理"，不中断）。

> **⚠ AR 病机制确认边界（与 ev-pvs1 v1.4.0 一致）**：遗传方式判定**不豁免**基因-疾病关联关。AR 病虽然跳过预测值评估（pLI/o/e/%HI，因隐性不适用），但**仍必须先过"基因-疾病关联 ≥ Moderate"关**——其核心判据为：**在 ClinVar search 数该基因 P/LP 截短变异（Frameshift+Nonsense+Splice site）≥3 个**（详见 ev-pvs1 第 1.1 步）。不得因"AR 直通"而跳过此关直接给 PVS1 满档。

> **证据来源铁律**：遗传方式判定一律以 ClinVar 患者基因型、PubMed 报道、ClinGen GenCC MOI 的真实查询为准，禁止凭基因名猜测或套用本 SKILL 案例。

> **外部阈值集中引用（P1-3 整改）**：本群全部子技能的外部阈值/切点（PM2 频率、REVEL 切点、SpliceAI 0.2、LOF 0.1%、BS1/BA1 基因特异阈值、PM3 累分表、cspec/PMID 版本等）**统一以本技能包 `config/thresholds.json` 为唯一口径**（`scripts/acmg_evidence.py`、`scripts/acmg_combine.py` 均读该表）；升版只改该文件一处，并触发全群重审。各 ev-* 子技能不再各自维护数值副本。
